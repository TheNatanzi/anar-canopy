Static site, no build step. Open `index.html` over a local server (`.claude/launch.json` serves the folder on port 5173) so the fonts, video and deferred scripts load normally.

## The hero (index first screen, HERO-V2 "APPROVED 02:05")

- Full-bleed muted looping video (`.hero__video`), `muted loop playsinline preload="none"`, poster `hero-poster-small.jpg` (141 KB). The `<video>` has no `src` in the HTML: `site.js` block 0 appends the mp4 `<source>` only after window `load`, only without `prefers-reduced-motion`, only when `navigator.connection.saveData` is not true, and not while motion is paused. `hero-1080-loop.mp4` (4.0 MB) above 768px, `hero-720-loop.mp4` (1.7 MB) at or below (the `media` attribute on `<source>` is ignored inside `<video>`). The video pauses when off screen. No WebM: the encode came out larger than the mp4.

Halo `.hero__halo`: a static `radial-gradient(closest-side, rgba(27,34,30,.6), transparent 70%)` (no `filter:blur`). On phones the logo is 78vw (51vw was too small to read).

### Reduced motion / no JS / content visible by default
- `document.documentElement.classList.add('js')` is the only inline script (one line, in every `<head>`). `.js` now only switches the header to `position:fixed` and shows the two ghost buttons; it hides nothing. The mobile nav links are visible by default (a deep-night strip under the bar, toggle hidden) and collapse into the drawer only once `site.js` has bound the toggle (`html.nav-ready`).
- Content is visible by default. Reveal targets are hidden only under `html.anim-ready`, which `initMotion()` in `site.js` adds inside a `try` right after `gsap.registerPlugin(ScrollTrigger)`; anything already inside the viewport is set visible in the same task (no flash). If init throws, `.anim-ready` is removed and `.reduced` is added, so nothing stays hidden. Under `.reduced` and under `@media (prefers-reduced-motion: reduce)` everything is visible, nothing scrubs, the strips are in place, the leaves are static.
- If a CDN script fails, `site.js` still runs: the nav, accordion, panel, form and skip link work, and `.reduced` shows all content.

## Formspree

The form on `index.html#inquire` posts to `https://formspree.io/f/FORMSPREE_ID`. **Replace `FORMSPREE_ID`** (one place: `<form class="form" action="…">` in `index.html`, marked with an HTML comment). Fields: names ("Your name(s)"), email, writing_as (the couple / a parent / another family member), reply_in (English / Persian / Dari / Urdu / Hindi / Punjabi), help_needed (Full planning / Wedding-day coordination / Not sure yet), which_days (optional: Engagement · Mehndi/Henna · Aghd/Nikah · Pheras/Anand Karaj · Reception/Walima · Not sure yet), phone, wedding_date (free text: "First wedding date (or season)"), city_or_venue (optional), guest_count, traditions[] (Sofreh Aghd · Nikah · Mehndi/Henna · Sangeet · Haldi · Pheras/Mandap · Anand Karaj · Reception · Walima · Nowruz/Yalda), budget_range (optional: Under $50k · $50–100k · $100–200k · $200k+ · Prefer not to say), message; honeypot `_gotcha`; `_subject` preset. Once the real id is in, `site.js` posts with `fetch` (`Accept: application/json`, 12 s `AbortController` timeout): the `#form-status` region (`role=status`, `aria-live=polite`) reports success, error or timeout ("try again"), entered values stay on every error, the submit button is restored in `finally`, and the form only resets on success. While the action still contains `FORMSPREE_ID` the browser posts normally. A WhatsApp link (`https://wa.me/19252639949`) sits next to the phone number under the form and in every footer.
